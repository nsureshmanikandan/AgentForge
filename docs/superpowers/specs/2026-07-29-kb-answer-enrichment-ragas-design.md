# KB Answer Enrichment + RAGAS Grounding + Agent KB Picker — Design Spec

**Date:** 2026-07-29  
**Status:** Approved for implementation  
**Branch:** feature/AgentForge1.1

---

## Problem

1. The KB query panel returns `answer`, `sources`, and `graph_entities` from the backend but the frontend only renders `answer` — sources and entities are silently discarded.
2. CreateAgent only allows file upload to create a new KB; there is no way to attach an existing KB to an agent.
3. No grounding validation — users cannot tell if an answer is well-supported by the KB or hallucinated.
4. No user feedback loop on KB answers — no thumbs up/down, no signal for KB quality improvement.
5. Answer formatting is plain markdown — no step-by-step structure, no source references, no related questions.

---

## Goals

- Enrich the KB query answer card: step-by-step answer, collapsible sources with snippets + relevance scores + View links, related questions, RAGAS grounding badge, 👍/👎 with quick-tag feedback.
- Add KB dropdown picker in CreateAgent so agents can attach any existing KB (not just upload a new one).
- Integrate RAGAS to compute Faithfulness, Answer Relevancy, and Context Recall — surfaced as a single "Grounding" score badge.
- Persist feedback (vote + tag) to DB for future KB quality analysis.

---

## Out of Scope

- Inline document viewer (View → opens a new tab or modal — out of scope for this iteration).
- Multi-KB per agent (Option B was not selected — one agent, one KB).
- Fine-tuning or reranking based on feedback (future).
- RAGAS async batch evaluation (RAGAS runs synchronously per query for now).

## Architecture

### Backend Changes

#### 1. RAGAS Integration (`backend/app/api/rag.py`, `requirements.txt`)

Install: `ragas>=0.1` (pure-Python, no LLM required for metric computation).

On every `/query` call:
```python
from ragas.metrics import faithfulness, answer_relevancy, context_recall
from ragas import evaluate
from datasets import Dataset

ragas_score = _compute_grounding(question, answer, contexts)
```

Return a single `grounding_score: float` (0.0–1.0), computed as:
```
grounding_score = mean(faithfulness, answer_relevancy, context_recall)
```

If RAGAS fails (timeout, import error), return `grounding_score: null` — never block the answer.

#### 2. Enriched Query Response Schema

New `QueryResponse` Pydantic model in `backend/app/schemas/rag.py` (new file):

```python
class SourceChunk(BaseModel):
    filename: str
    snippet: str          # first 200 chars of the chunk
    score: float          # cosine similarity score
    doc_id: str           # KB document id for View link

class QueryResponse(BaseModel):
    answer: str
    sources: list[SourceChunk]
    graph_entities: list[dict] | None   # Graph KB only
    related_questions: list[str]        # 3 auto-generated
    grounding_score: float | None
```

`related_questions` generated by a follow-up LLM call:
```python
prompt = f"Given this answer about '{question}', generate 3 short follow-up questions a user might ask next. Return as JSON array."
```

#### 3. Feedback Endpoint

`POST /api/rag/knowledge-bases/{kb_id}/feedback`

```python
class FeedbackRequest(BaseModel):
    question: str
    answer: str
    vote: Literal["up", "down"]
    comment: str | None   # free-text from "What was wrong?" text box
```

Stored in new `kb_feedback` table:
```sql
CREATE TABLE kb_feedback (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    kb_id UUID REFERENCES knowledge_bases(id) ON DELETE CASCADE,
    question TEXT,
    answer TEXT,
    vote VARCHAR(4),   -- 'up' or 'down'
    comment TEXT,
    user_id UUID REFERENCES users(id),
    created_at TIMESTAMPTZ DEFAULT now()
);
```

Add Alembic migration.

#### 4. KB Listing for Agent Picker

`GET /api/rag/knowledge-bases` already exists and returns all KBs for the current user — no new endpoint needed. CreateAgent will call this on mount.

#### 5. Agent `knowledge_base_id` wiring

`AgentCreate` / `AgentOut` already have `knowledge_base_id: str | None`. No schema change needed. The frontend picker sets this field on submit.

## Data Flow

```
User types question
      ↓
POST /rag/knowledge-bases/{id}/query
      ↓
RAGEngine.query() / GraphEngine.query()
  → retrieve top-k chunks (cosine similarity)
  → build context string
  → LLM generates answer
  → RAGAS scores computed (async if > 2s, fallback null)
  → LLM generates 3 related questions
      ↓
QueryResponse { answer, sources[], graph_entities, related_questions, grounding_score }
      ↓
Frontend renders KBAnswerCard
  → Answer (ReactMarkdown)
  → Sources (collapsible, with snippets + scores + View links)
  → Graph entities (violet tags, Graph KB only)
  → Related questions (pill chips → re-run query)
  → Grounding badge (colour-coded)
  → 👍/👎 → tag row → POST /feedback
```

## Risks

| Risk | Mitigation |
|------|------------|
| RAGAS adds 2–4s to query latency | Run RAGAS after returning answer (async), show score when ready or null |
| RAGAS `datasets` dependency is large (~200MB) | Install only; lazy-import inside function |
| `related_questions` LLM call adds latency | Run in parallel with RAGAS; return `[]` on failure |
| Agent KB picker breaks existing auto-create KB flow | Keep upload path as fallback; only change UI, not API |
